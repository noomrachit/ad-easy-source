# Ad Easy

เว็บแอปบันทึกและติดตามผลแคมเปญโฆษณา Facebook / Instagram / TikTok ภาษาไทย
มีระบบสมาชิก ฐานข้อมูล PostgreSQL และการนำเข้ารายงาน CSV จาก Ads Manager

## วิธีนำขึ้น Railway

1. สร้าง GitHub repository ใหม่ แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้เข้าไป
2. ใน Railway สร้าง project ใหม่ → Deploy from GitHub repo → เลือก repo นี้
3. ในโปรเจกต์เดียวกัน กด New → Database → Add PostgreSQL
4. ไปที่ service ของแอป → Variables → เพิ่มตัวแปร

   `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`

5. ไปที่ Settings → Networking → Generate Domain

เสร็จแล้วเปิดโดเมนที่ได้ สมัครสมาชิกแล้วใช้งานได้เลย ตารางในฐานข้อมูลถูกสร้างอัตโนมัติตอนเริ่มระบบ

## ตัวแปรสภาพแวดล้อม

| ตัวแปร | จำเป็น | คำอธิบาย |
|---|---|---|
| `DATABASE_URL` | ใช่ | สายเชื่อมต่อ PostgreSQL — ถ้าไม่ใส่จะใช้ที่เก็บในหน่วยความจำ ข้อมูลหายเมื่อรีสตาร์ท |
| `PORT` | ไม่ | Railway ใส่ให้อัตโนมัติ |
| `ADMIN_KEY` | ไม่ | รหัสลับสำหรับดึงรายชื่ออีเมลสมาชิก **ถ้าไม่ตั้งไว้ ทางนี้จะปิดสนิท** ตั้งเป็นข้อความยาว ๆ เดาไม่ได้ |

## ดึงรายชื่ออีเมลคนที่ยินยอมรับข่าวสาร

ตั้ง `ADMIN_KEY` ก่อน แล้วเปิดลิงก์นี้ในเบราว์เซอร์ (ไฟล์ CSV จะดาวน์โหลดลงมา):

```
https://โดเมนของคุณ/api/subscribers?key=รหัสลับของคุณ
```

อยากดูจำนวนเฉย ๆ ไม่ต้องโหลดไฟล์ ให้เติม `&format=json` ต่อท้าย

**อย่าเอาลิงก์นี้ไปแปะที่ไหน** ใครมีรหัสลับก็ดึงรายชื่อไปได้ ถ้าหลุดให้เปลี่ยนค่า `ADMIN_KEY` ใหม่ทันที
รายชื่อที่ได้จะมีเฉพาะคนที่ติ๊กยินยอมตอนสมัครเท่านั้น คนที่ไม่ติ๊กจะไม่อยู่ในไฟล์

## รันบนเครื่องตัวเอง

```
node server.js
```

ไม่ใส่ `DATABASE_URL` จะรันด้วยที่เก็บในหน่วยความจำ เหมาะสำหรับลองดูหน้าตาเท่านั้น

## โครงสร้าง

- `server.js` — เซิร์ฟเวอร์ HTTP และ API (ใช้ Node built-ins ล้วน ไม่มี framework)
- `store-pg.js` — ชั้นข้อมูล PostgreSQL (ใช้งานจริง)
- `store-mem.js` — ชั้นข้อมูลในหน่วยความจำ (สำหรับทดสอบ)
- `public/` — หน้าเว็บทั้งหมด

## ความปลอดภัย

- รหัสผ่านเข้ารหัสด้วย scrypt พร้อม salt เฉพาะรายบุคคล ไม่เก็บรหัสผ่านตรงๆ
- session token สุ่ม 32 ไบต์ เก็บในฐานข้อมูล เพิกถอนได้ตอนออกจากระบบ
- คุกกี้เป็น HttpOnly และ SameSite=Lax เพิ่ม Secure อัตโนมัติเมื่ออยู่บน HTTPS
- ทุกคำสั่งฐานข้อมูลผูกกับ user_id เสมอ ผู้ใช้เห็นและแก้ได้เฉพาะข้อมูลของตัวเอง
- ใช้ parameterized query ทั้งหมด ไม่มีการต่อสตริง SQL
- จำกัดการลองเข้าสู่ระบบผิดไม่เกิน 10 ครั้งต่อ 15 นาที

## ข้อจำกัดที่ควรบอกผู้ใช้

แอปนี้ไม่ได้เชื่อมต่อกับบัญชีโฆษณาโดยตรง การเพิ่มแคมเปญที่นี่ไม่ได้ทำให้โฆษณายิงออกไปจริง
ใช้สำหรับบันทึกและติดตามผลเท่านั้น ตัวเลขมาจากการกรอกเองหรือนำเข้าไฟล์ CSV
